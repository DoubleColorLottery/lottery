# Claude Code Instructions

## Repo Layout

- `apps/web`: Nuxt frontend and Nitro backend
- `packages/contracts`: Solidity, Foundry tests, deployment, and admin scripts

## Common Commands

```bash
bun run dev
bun run build
bun run test
bun run test:contracts
bun run test:web
bun run test:fork
bun run verify:flap-port
bun run audit:contracts
```

## Contract Workflow

```bash
bun run --cwd packages/contracts build
bun run --cwd packages/contracts test
bun run --cwd packages/contracts test:fork
bun run --cwd packages/contracts sync:abi
bun run --cwd packages/contracts audit:slither
```

## Web Workflow

```bash
bun run --cwd apps/web dev
bun run --cwd apps/web build
bun run --cwd apps/web test
bun run --cwd apps/web test:e2e:flap-eligibility
```

## Important Notes

- ABI JSONs consumed by the web app live in `apps/web/config/` and are generated from `packages/contracts`.
- The token launch and tax path uses Flap Tax Token V3 and VaultPortal.
- The repo targets SurrealDB server v3 with the current JavaScript SDK line (`surrealdb` 2.x).
- `docker compose up --build` starts both the Nuxt app and a SurrealDB v3 container with persistent `surrealkv://` storage.
- Production Dokploy uses the live compose with database and scheduled workers enabled.
- Tax revenue is dispatched through Flap's TaxProcessor and forwarded by the revenue vault before new rounds.
- Eligibility is indexed offchain and authorized with server-signed EIP-712 balance certificates.
- Secrets should come from environment variables, not committed defaults.

# RTK (Rust Token Killer) - Token-Optimized Commands

## Golden Rule

**Always prefix commands with `rtk`**. If RTK has a dedicated filter, it uses it. If not, it passes through unchanged. This means RTK is always safe to use.

**Important**: Even in command chains with `&&`, use `rtk`:
```bash
# ❌ Wrong
git add . && git commit -m "msg" && git push

# ✅ Correct
rtk git add . && rtk git commit -m "msg" && rtk git push
```
